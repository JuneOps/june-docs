Connect your Kandji tenant with June for modern Mac device management and comprehensive asset tracking.

## What you'll accomplish
- Generate API access token in Kandji
- Configure the June integration  
- Understand Kandji data mapping
- Review what June syncs and when

## Prerequisites

Before starting the integration, ensure you have:
- Kandji tenant with API access
- Admin or appropriate API permissions in Kandji
- The Admin or Owner role in June
- Understanding of your Kandji device management setup

## Setup Process

### Step 1: Generate API Token in Kandji

<Steps>
  <Step title="Access Kandji Settings">
    1. Log into your Kandji tenant
    2. Navigate to **Settings** in the left sidebar
    3. Go to **Access** section
    4. Select **API Token**
  </Step>
  
  <Step title="Create New Token">
    1. Click **Generate New Token**
    2. Enter a descriptive name: "June Integration Token"
    3. Set appropriate permissions (see permissions section below)
    4. Click **Generate**
  </Step>
  
  <Step title="Copy and Secure Token">
    1. **Immediately** copy the generated token
    2. Store it securely - you won't be able to view it again
    3. Note the creation date for future reference
  </Step>
</Steps>

### Step 2: Configure Token Permissions

Give the token these permissions:

- **Tenant Details**: used to test the connection.
- **Users**: matches devices to employees.
- **Blueprints**: read access.
- **Audit Log**: read access.
- **Tags Management**: read and write access.
- **Devices** > **Device Information**, including **Update Device**: syncs devices, their apps and activity, and sends the assignee set in June back to Kandji.
- **Prism** > **Application Firewall**: reads each Mac's firewall status. Without it, device sync fails.
- **Devices** > **Device Actions** (optional): delete, restart, shut down and update inventory.
- **Devices** > **Device Secrets** (optional): shows a device's secrets when an admin asks. June doesn't store them and fetches them on demand.


### Step 3: Connect Kandji in June

<Steps>
  <Step title="Access June Integrations">
    1. Log into June
    2. Go to **Settings** > **Integrations**
  </Step>
  
  <Step title="Select Kandji">
    1. Select **Kandji** under **Available Integrations** (in the **Mobile Device Management** group)
  </Step>
  
  <Step title="Enter Kandji Details">
    Provide the following information:
    - **Your Kandji API URL**: Your Kandji organization API URL (e.g., `https://yourcompany.api.kandji.io`).
    - **API Access Token**: The token generated in Step 1
    
    Then click **Connect**.
  </Step>
  
  <Step title="Test Connection">
    1. When you click **Connect**, June tests the connection by reading your tenant's license details
    2. If the test succeeds, the integration shows **Connected**
    3. To test again later, open the **Connected** menu on the integration's page and select **Test Connection**
  </Step>
</Steps>

### Step 4: Review What June Syncs

<Steps>
  <Step title="Sync Schedule">
    June syncs with Kandji once a day.
  </Step>
  
  <Step title="Capabilities">
    The **Capabilities** section on the integration's page lists what June syncs from Kandji:
    - Sync all devices (always on)
    - Sync all employees
    - Sync Software Applications (installed apps)
    
    It also lists the device actions June can take in Kandji: delete a device, restart, shut down, force a check-in, and look up a device's unlock PIN, recovery password, FileVault key or Activation Lock bypass code.
  </Step>
</Steps>

### Step 5: Your first sync

<Steps>
  <Step title="Your first sync">
    The first sync starts automatically when you connect. To sync again at any time, open the **Connected** menu on the integration's page and select **Sync Now**.
  </Step>
</Steps>

## Data Synchronization

### What Gets Synced

|Data Type | Kandji Source | June Destination | Notes |
|-----------|----------------|------------------|--------|
| **Device Identity** | Device Name, Serial Number, Asset Tag, Tags | Device Name, Serial Number, Asset Tags | Primary device identification |
| **Hardware Info** | Model, Processor, Memory, Storage | Hardware Specifications | Complete hardware inventory |
| **Software** | Operating System, Software Applications | System Info, App Inventory | OS version and installed apps |
| **User Assignment** | User and Location fields | Employee Assignment | Links devices to users |
| **Compliance** | Last Inventory, Check-in Status | Health Status | Device connectivity and compliance |
| **Department Data** | Department of the device's user | Department | Organizational groupings |

## Troubleshooting

### Common Authentication Issues

<AccordionGroup>
  <Accordion title="Invalid API Token">
    **Symptoms**: "Failed to connect to Kandji" when you connect or test the connection
    
    **Solutions**:
    - Verify the API token was copied correctly
    - Ensure that the *Tenant Details* permission is enabled.
    - Check if the token has been revoked or expired
    - Ensure sufficient permissions were granted to the token
    - Select **Test Connection** from the **Connected** menu to test again.
  </Accordion>
  
  <Accordion title="Insufficient Permissions">
    **Symptoms**: "Access denied" errors for specific operations
    
    **Solutions**:
    - Review token permissions in Kandji settings
    - Ensure all required permissions are enabled
    - Check if permissions were modified after token creation.
    - Edit the token permissions in Kandji and save.
    - Select **Test Connection** from the **Connected** menu to test again.
  </Accordion>
  
  <Accordion title="Subdomain Issues">
    **Symptoms**: "Tenant not found" or connection errors
    
    **Solutions**:
    - Verify the Kandji organization API URL is correct. You must enter the full URL https://subdomain.api.kandji.io
    - Check for typos in the subdomain field
    - Ensure the Kandji tenant is active and accessible
    - Test direct access to Kandji web interface
  </Accordion>
</AccordionGroup>

### Sync Issues

<AccordionGroup>
  <Accordion title="Missing Devices">
    **Possible Causes**:
    - Devices not enrolled in Kandji
    - Devices haven't checked in recently
    - Insufficient permissions to access certain devices
    
    **Solutions**:
    - Verify device enrollment status in Kandji
    - Check last inventory date for missing devices
    - Confirm API permissions cover all required devices
  </Accordion>
  
  <Accordion title="Outdated Information">
    **Possible Causes**:
    - Devices not checking in regularly
    - The last sync ran before the change
    - Network issues preventing updates
    
    **Solutions**:
    - Select **Sync Now** from the **Connected** menu on the integration's page to pull the latest data from Kandji. Kandji only has new inventory after a device checks in.
    - Check device connectivity and management status
    - Check the **Activity** section on the integration's page for specific error messages
  </Accordion>
  
  <Accordion title="Performance Problems">
    **Symptoms**: Slow syncs or timeouts
    
    **Solutions**:
    - Large environments take longer to sync. Follow progress in **Sync Status** on the integration's page.
    - If a sync fails, check the **Activity** section for the error and contact June support
  </Accordion>
</AccordionGroup>
