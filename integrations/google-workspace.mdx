Connect your Google Workspace environment with June to enable secure API-based access to users, groups, and organizational data for automated employee data synchronization.

For permission-aware Knowledge sources from shared drives, connect [Google Drive](/integrations/google-drive) separately: go to **Settings** > **Integrations** and select **Google Drive** in the **Knowledge** group.

## What you'll accomplish
- Authorize June to access your Google Workspace data
- Sync your employees, office locations, and the apps people sign in to with Google
- Let June manage groups, calendar access, and user accounts when you ask

## Capabilities

Once connected, June provides the following capabilities for Google Workspace:

### Data Synchronization

| Capability | Description |
|------------|-------------|
| **Sync all employees** | Sync all your employees into June. For IDP integrations, this is always on. |
| **Sync locations** | Sync all your office locations into June. |
| **Sync Software Applications** | Sync all your software applications into June. |

### Group Management

| Capability | Description |
|------------|-------------|
| **Add user to Google group** | Add an employee to a Google Group so they receive the group's email, calendar invites, and access permissions. |
| **Remove user from Google group** | Remove an employee from a Google Group to stop their group email, calendar invites, and access permissions. |
| **Create Google group** | Create a new Google Group for email distribution, calendar invites, and managing shared access. |
| **Delete Google group** | Delete a Google Group and remove all its members. |
| **List Google groups** | Retrieve a list of Google Groups in Google Workspace, optionally filtered by a search query. |
| **Get Google group details** | Retrieve detailed information about a specific Google Group. |
| **List employee's Google groups** | List all Google Groups that an employee is a member of. |

### User Management

| Capability | Description |
|------------|-------------|
| **Create Google Workspace user** | Create a new user account in Google Workspace. |
| **Suspend Google Workspace user** | Suspend a user so they can't sign in. |
| **Unsuspend Google Workspace user** | Restore sign-in for a suspended user. |
| **Reset Google Workspace user password** | Reset a user's password. |
| **Get Google Workspace user details** | Look up a user's account details. |

### Calendar Management

| Capability | Description |
|------------|-------------|
| **Add user to Google Calendar** | Grant an employee access to a Google Calendar by adding them as a reader, writer, or owner. |
| **Remove user from Google Calendar** | Remove an employee's access to a Google Calendar. |

## Prerequisites

Before starting the integration, ensure you have:
- Google Workspace Super Admin access
- The Admin or Owner role in June

## Permissions and Data Access

June requests the following permissions when you connect Google Workspace:

### Read-Only Permissions

| Scope | Purpose |
|-------|---------|
| `admin.directory.user.readonly` | Syncs your user directory: names, emails, status, org units, managers, and addresses, so June knows your employees |
| `admin.directory.group.readonly` | Looks up Google Groups and their members when you ask June about a group |
| `admin.directory.resource.calendar.readonly` | Reads your Workspace buildings to create office locations in June |
| `admin.directory.device.chromeos.readonly` | Requested when you connect. June doesn't read ChromeOS devices today. |
| `admin.directory.device.mobile.readonly` | Requested when you connect. June doesn't read mobile devices from Google Workspace today. |
| `admin.reports.audit.readonly` | Reads sign-in and app authorization events, so June can show which apps people sign in to with Google, and searches email logs when you ask |
| `admin.reports.usage.readonly` | Requested when you connect. June doesn't read usage reports today. |

### Write Permissions

| Scope | Purpose |
|-------|---------|
| `admin.directory.group` | Managing Google Groups: create, update, and delete groups for automated team management |
| `admin.directory.group.member` | Managing group memberships: add or remove users from groups for access control automation |
| `admin.directory.user` | User lifecycle management: create, suspend, restore, and update user accounts for automated provisioning |
| `calendar` | Calendar sharing management: add or remove a user's access to shared calendars during onboarding/offboarding. June uses it only to change who can access a calendar. June does not read, create, or modify calendar events. |
| `gmail.settings.sharing` | Requested when you connect. June doesn't change Gmail settings today. |
| `gmail.settings.basic` | Requested when you connect. June doesn't change Gmail settings today. |

<Note>
Write permissions let June manage groups, calendar access, and user accounts for onboarding, offboarding, and access requests. You can see each action June took, and who approved it, in the chat or runbook run where it happened.
</Note>

## Google Workspace OAuth Integration

<Steps>
  <Step title="Access Integrations">
    1. Log into June
    2. Go to **Settings** > **Integrations**
    3. Select **Google Workspace** under **Available Integrations** (in the **Identity Providers** group)
    4. Click **Connect** to begin the Google sign-in
  </Step>
  
  <Step title="Authorize June Access">
    1. You'll be redirected to Google's authorization page
    2. Sign in with your Google Workspace Super Admin account
    3. Review the permissions June is requesting
    4. Click **Allow** to grant June access to your Google Workspace data. 
    5. If you see a message saying "Access blocked: Authorization Error" or "admin_policy_enforced" error during OAuth flow, please follow the troubleshooting steps below to resolve the issue.
  </Step>
  
  <Step title="Complete Integration Setup">
    1. After authorization, you'll be redirected back to June
    2. If the integration is successful, you see the message "Connection Successful" and the integration shows **Connected**.
  </Step>
  
  <Step title="Test the Integration">
    1. Click on the dropdown menu that has the status of the integration
    2. Click **Test Connection**
    3. If the test succeeds, you see "Test Successful".
    4. If the test fails, you see "Test Failed" with the reason, and the integration shows **Not Connected**.
    5. Please follow the troubleshooting steps below to resolve the issue.
  </Step>

  <Step title="Sync data from Google Workspace">
    1. The first sync starts automatically when you connect. After that, June syncs once a day.
    2. To sync sooner, click on the dropdown menu that has the status of the integration and click **Sync Now**.
    3. You should see the employees from Google Workspace in June under **Employees** > **All Employees**.
  </Step>
</Steps>

## Troubleshooting

### Common Integration Issues

<AccordionGroup>
  <Accordion title="OAuth Authorization Blocked">
    **Symptoms**: "Access blocked: Authorization Error" or "admin_policy_enforced" error during OAuth flow
    
    **Solutions**:
    If your organization has strict third-party app policies, you'll need to explicitly trust June's OAuth application:
    
    1. Get June's OAuth Client ID. If Google Workspace is already connected (for example, you're reconnecting), go to **Settings** > **Integrations**, select **Google Workspace** under **Configured Integrations**, open the menu next to the integration status, and click **Copy Client ID**. Otherwise, ask June support for the Client ID.
    2. Keep the Client ID ready for step 8
    3. Continue in Google Admin Console
    4. Go to [Google Admin Console](https://admin.google.com) and sign in as a Super Admin
    5. Navigate to **Security > Access and data control > API Controls**
    6. Under **API Controls**, click **Manage Third-Party App Access**
    7. Click **Add app > OAuth App Name or Client ID**
    8. Paste the June OAuth Client ID from step 1
    9. Select **Trusted** as the access level
    10. Click **Configure** and save changes
    11. Return to June and retry the OAuth authorization flow
  </Accordion>
  
  <Accordion title="Integration Test Failed">
    **Symptoms**: Integration shows **Not Connected** after Google sign-in
    
    **Solutions**:
    - Ensure you authorized with a Google Workspace Super Admin account
    - Verify your organization allows third-party app access
    - Check if you have any conditional access policies blocking API access
    - Select **Reconnect** from the integration's menu to sign in again
    - Contact June support if the issue persists
  </Accordion>
  
  <Accordion title="Sync Problems">
    **Symptoms**: Users not syncing or outdated information
    
    **Solutions**:
    - Verify the authorized admin account has access to all organizational units
    - Check if users are suspended or in organizational units with restricted access
    - Review Google Workspace audit logs for API access issues
    - Ensure users have the required attributes (email, name, etc.) populated
    - Run **Sync Now** and check the **Activity** section on the integration's page for error messages
  </Accordion>
</AccordionGroup>
