A runbook is an end-to-end workflow that June runs on its own once it starts. You describe the process in plain language, along with the actions June may take, and June follows it whenever one of its triggers fires: on demand, on a schedule, or when a chat, employee request or Jira ticket matches. See [Triggers](#triggers).

Runbooks live in the sidebar under **Intelligence** > **Runbooks**.

## Triggers

A trigger decides when June can use the runbook. A runbook has 1 to 10 triggers.

- **Manual:** runs when someone clicks **Run now**. One per runbook.
- **Schedule:** runs daily, weekly, monthly or on a custom schedule, at most once per day, in the time zone you pick. For weekdays, use a custom schedule.
- **Agent task:** June offers the runbook with a **Start** button when an IT user asks in the Agent or works an IT request. Describe when it applies.
- **Employee Request:** runs when an eligible employee's request matches.
  - Choose all employees or set conditions such as type, department, group or location, with exclusions.
  - Each action can have an approval chain, off by default: the requester's manager or named people, with any or all approvers, nudges and escalation.
- **Jira:** runs when a Jira ticket matching your conditions is created. Pick a Jira site and project, then add conditions. All must match.

**Manual** and **Schedule** can be combined. **Agent task**, **Employee Request** and **Jira** each stand alone. Jira must be connected and synced, or the condition choices don't load. If a scheduled run is still unfinished when the next is due, June skips the new one.

Switching a runbook to **Employee Request** clears its instructions, tools and other triggers. June asks you to confirm first.

## Create a runbook

<Steps>
  <Step title="Start">
    Click **New Runbook**, or pick a Quick start, and name it.
  </Step>
  <Step title="Add triggers">
    Add one or more triggers from the list above.
  </Step>
  <Step title="Write instructions">
    Describe what June should do, which constraints matter, and what the result should contain.
  </Step>
  <Step title="Add actions">
    Type `/` to insert a tool that changes something and set its inputs, or leave an input to be worked out when the runbook runs. A new action runs without asking (**Autonomous**, the default), except in the cases listed in [When June acts without asking](/agents/agent#when-june-acts-without-asking). Turn off **Autonomous** to require approval each time. If June needs a write action you didn't place, it asks for approval each time. Looking things up needs no setup. See [Tools](/agents/tools).
  </Step>
  <Step title="Check and publish">
    **Save Draft** saves without checks. **Validate** checks only. **Publish** checks, then publishes and activates if every check passes. If a check fails, the runbook stays a draft.
  </Step>
</Steps>

### Quick starts

Quick starts are ready-made runbooks on the Runbooks page, shown when you have matching data. Most run every Monday at 2:00 PM Eastern, and you can also run them manually. When Slack has a notifications channel, they add a summary to IT. On a software app's **Runbooks** tab, **New runbook** > **Start with a template** offers two more, **Software Usage Report** and **Software Usage Employee Survey** (needs Slack).

### Example: find devices that stopped checking in

Open **Devices Missing Check-In** from Quick starts. It arrives with a Manual trigger, a weekly schedule and instructions already filled in. Change the schedule or time zone if you need to, validate it, and test it in the playground. Choose the mock result for the Slack summary so nothing real is sent. Then publish. Use **Run now** to try it at once. Each Monday after that, June runs it, and if Slack has a notifications channel, IT gets a summary there.

## Who can do what

| Task | Permission shown in Roles | Built-in roles |
|---|---|---|
| View runbooks, drafts and run history | Runbooks, drafts & revisions; Runbook run history & results | Member, Software Procurement, Admin, Owner |
| Create a runbook | Create runbooks | Admin, Owner |
| Edit, restore versions | Edit runbooks | Admin, Owner |
| Delete | Delete runbooks & drafts | Admin, Owner |
| Run now, test in the playground | Run runbooks | Admin, Owner |
| Publish, activate, deactivate | Publish & activate runbooks | Admin, Owner |
| Approve actions | Approve Agent & Runbook tool actions | Admin, Owner |

**Create runbooks** lets someone edit their own unpublished new drafts. Editing someone else's draft, or a draft of an existing runbook, needs **Edit runbooks**. To let a teammate edit but not publish, give a custom role those two permissions without **Publish & activate runbooks**. See [Members and roles](/admin/roles).

## Test before you publish

Click **Test** on a runbook to open the playground. Choose how to simulate a start, such as a test employee request, a scheduled run, an agent task or a Jira ticket.

- Actions that change something ask whether to use a mock result, run the real action after you confirm, or reject it.
- Approvals are simulated, and no approval request is sent.

## Statuses and lifecycle

A runbook is:

- **Active:** its triggers are live.
- **Inactive:** its triggers are off. New runbooks start inactive until published. Restored runbooks stay inactive until you activate them.
- **Deleted:** its triggers stopped. Run history is kept, and you can restore it.

A draft can be:

- **Needs review:** an action needs to be placed in the instructions or confirmed.
- **Needs a change:** a check found a problem.
- **Couldn't finish:** the check didn't complete. Validate again.

Other things to know:

- **Stop runbook** ends a run. The run records who stopped it.
- **Edit** opens a draft of the published runbook. The published version doesn't change until you publish.
- Deactivating stops the triggers. **Delete** is blocked while any run is unfinished.
- **Revision history** lists versions. Restoring one opens it in the editor, and you save to apply it. This needs **Edit runbooks**.

## What runbooks produce

**What June learned** on a runbook's page holds notes June keeps from each test and real run. Your instructions always come first, and you can add notes or restore an earlier version.

A runbook can save what it finds as findings, which you can filter by status and severity. It can also send employees a [reachout](/agents/reachouts) by Slack or email.

When a manual, scheduled or Jira run fails, June posts the runbook name with **Open in June** in your Slack notifications channel. See [Slack](/integrations/slack).

## Run history

**Runbooks** > **Run history** lists every run. Switch views to see manual and scheduled runs, runs started by Jira tickets, or runs from requests and chats. Scheduled runs show **Automatic**. A lock marks a **Private run**, visible only to the person who started it. A run from an employee request opens the request in [Requests](/help-desk/requests).

## If something looks wrong

<AccordionGroup>
  <Accordion title="Publish didn't work">
    Open the validation panel. **Changes needed** must be fixed, and **Review** items need a look. If the runbook changed after validation, or the available tools changed, validate again. A tool from an unconnected integration blocks validation until you connect it.
  </Accordion>
  <Accordion title="Run now is greyed out">
    The runbook is inactive, it has no Manual trigger, or another manual or scheduled run is queued, running or waiting. Finish or stop that run first.
  </Accordion>
  <Accordion title="Employees' requests don't use my runbook">
    It must be active, with an **Employee Request** trigger, and the employee must match the eligible employees. Every action must be marked **Available for self-service**. See [Tools](/agents/tools#employee-self-service).
  </Accordion>
</AccordionGroup>

## FAQ

<AccordionGroup>
  <Accordion title="Which tools can a runbook use?">
    Any tool from a connected integration, and your custom tools. Employee Request runbooks can use only self-service tools. Published runbooks use their own configured tools, not the viewer's role.
  </Accordion>
</AccordionGroup>
